Getting started

This guide takes you from installing Ravengram to a working bot or user-account script. It assumes you know basic Python and async/await.

Install

Ravengram needs Python 3.10 or newer. It isn't on PyPI yet, so install it from GitHub:

shell
pip install git+https://github.com/ahmedahah4/ravengram

Two optional extras are available:

shell
# TgCrypto (C-accelerated encryption) and uvloop
pip install "ravengram[fast] @ git+https://github.com/ahmedahah4/ravengram"

# Log in by scanning a QR code
pip install "ravengram[qrcode] @ git+https://github.com/ahmedahah4/ravengram"

The package installs as pyrogram, so you import it with from pyrogram import .... See Coming from Pyrogram for what that means.

API credentials

Every Telegram client identifies itself with an API ID and API hash. Getting them is free:

  1. Log in at my.telegram.org/apps with your phone number.
  2. Fill in the Create new application form. The app name and short name can be anything.
  3. Copy the api_id (a number) and api_hash (a 32-character string).

Treat the API hash like a password. Keep it out of public repositories, for example by reading it from an environment variable.

Your first script

This script logs in with your own account and sends a message to your Saved Messages:

hello.py
import asyncio
from pyrogram import Client

api_id = 12345
api_hash = "0123456789abcdef0123456789abcdef"


async def main():
    async with Client("my_account", api_id, api_hash) as app:
        await app.send_message("me", "Greetings from Ravengram!")


asyncio.run(main())

The first time you run it, Ravengram asks for your phone number and the login code Telegram sends you, then saves the login to my_account.session. Later runs reuse that file, so you won't be asked again and you can leave out api_id and api_hash.

Running a bot

Create a bot with @BotFather to get a bot token, then pass it as bot_token. Bots still need an API ID and hash.

echo_bot.py
from pyrogram import Client, filters

app = Client(
    "echo_bot",
    api_id=12345,
    api_hash="0123456789abcdef0123456789abcdef",
    bot_token="123456:ABC-DEF...",
)


@app.on_message(filters.command("start"))
async def start(client, message):
    await message.reply("Send me anything and I'll echo it back.")


@app.on_message(filters.text & filters.private)
async def echo(client, message):
    await message.reply(message.text)


app.run()

app.run() starts the client, keeps it running until you press Ctrl+C, then stops it cleanly.

Handlers and filters

A handler is a function that runs when a certain kind of update arrives. You register it with a decorator such as @app.on_message, @app.on_callback_query, @app.on_edited_message or @app.on_message_reaction. There are 30 handler types.

A filter decides which updates a handler receives. Combine filters with & (and), | (or) and ~ (not):

filters.py
# Photos or videos in groups, but not ones you sent yourself
@app.on_message((filters.photo | filters.video) & filters.group & ~filters.me)
async def media(client, message):
    ...


# Messages matching a regular expression
@app.on_message(filters.regex(r"^hello"))
async def greet(client, message):
    ...

Some commonly used filters:

FilterMatches
filters.command("x")Commands such as /x
filters.privateMessages in one-to-one chats
filters.groupMessages in groups and supergroups
filters.textText messages
filters.photoPhoto messages
filters.meMessages sent by your own account
filters.incomingMessages received rather than sent
filters.regex(p)Text that matches the pattern p

The raw API

High-level methods cover the common tasks. For everything else, every function in Telegram's schema is available under pyrogram.raw.functions and can be sent with app.invoke():

raw_call.py
from pyrogram import raw

config = await app.invoke(raw.functions.help.GetConfig())

Raw calls return raw objects from pyrogram.raw.types, which follow Telegram's schema directly. They are less convenient than the high-level types, but let you use any Telegram feature as soon as it's in the schema. To receive raw updates, use @app.on_raw_update().

Sessions

A session holds your login. By default it's a SQLite file named after the client, stored in the working directory. Other options:

  • in_memory=True keeps the session in memory only. Nothing is written to disk and you log in on every run.
  • await app.export_session_string() returns the session as a string. Pass it back with session_string="..." to log in without a file, which is useful on servers and in containers.
  • workdir="path" changes where session files are stored.

A session file or string gives full access to the account. Never share it or commit it to a repository.

Coming from Pyrogram

Ravengram is a drop-in replacement. It installs under the same pyrogram import name and keeps the same API, so most existing code runs without changes. Uninstall pyrogram (or another fork) first, because only one package can own the pyrogram name in an environment.

Staying up to date

The raw API is generated from Telegram's schema (currently Layer 229). A daily workflow detects schema changes and opens a pull request with the regenerated code. After it's merged, update your install:

shell
pip install --upgrade --force-reinstall git+https://github.com/ahmedahah4/ravengram

Found a bug or missing feature? Open an issue on GitHub.
